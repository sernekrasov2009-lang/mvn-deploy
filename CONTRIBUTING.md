# Участие в разработке

Спасибо, что хотите помочь! Ниже всё, что нужно для первого pull request.

## Быстрый старт

```bash
git clone https://github.com/sernekrasov2009-lang/mvn-deploy.git && cd mvn-deploy
sudo apt install shellcheck shfmt     # или dnf/pacman/brew
bash tests/lint.sh                    # bash -n, ShellCheck, shfmt, поиск секретов, unit-тесты
```

Форматирование: `shfmt -w -i 2 -ci -sr <файлы>`. Перед коммитом `bash tests/lint.sh` должен проходить.

## Правила

- Только bash; без `eval` и без `source` пользовательских данных.
- Пакеты, службы и firewall — только через функции из `platform.sh` и `firewall.sh` (не вызывайте `apt`/`systemctl`/`ufw` напрямую).
- Любое изменение системы записывайте в состояние, чтобы `uninstall.sh` мог его откатить.
- Необязательные возможности при сбое не должны прерывать установку.
- Новая логика сопровождается тестом в `tests/unit.sh`. Для разбора вывода утилит добавляйте пример в тест.
- Сообщения для пользователя: ясно, что произошло и что делать дальше.

## Как предложить изменение

1. Откройте issue с описанием (шаблоны есть) либо сразу pull request для небольших правок.
2. Одна тема — один pull request. Обновите `CHANGELOG.md` и документацию, если поведение изменилось.
3. CI запускает линт, dry-run на 16 дистрибутивах и реальную установку на Ubuntu. Красный CI блокирует слияние.

## Проверка на живом сервере

Используйте временный VPS. Запускайте `--dry-run`, затем установку, затем `mvn-deploy doctor`. В issue приложите вывод и `/var/log/mvn-deploy/install.log` (пароли в нём маскируются, но просмотрите его перед отправкой).
